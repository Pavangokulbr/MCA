# 03 Chapter Structure

Use this universal order unless the institution explicitly changes it:

1. Introduction
   - Project introduction
   - Background of study
   - Statement of objectives

2. Software Requirement Analysis
   - Hardware specification
   - Software specification
   - About software/system and features

3. System Analysis
   - Existing system
   - Proposed system
   - Feasibility study

4. System Design
   - DFDs (for database-oriented projects)
   - UML diagrams:
     - Class
     - Interaction (Sequence and Collaboration)
     - Object
     - Use case
     - Control flow

5. Database Design (if applicable)
   - ER diagrams
   - Functional dependencies and normalization

6. Coding / Code Templates
   - Module-wise functionality
   - Class-wise methods with input/output parameters
   - For database projects:
     - Tables (fields, data types, keys, constraints)
     - Stored procedures (PL/SQL), where relevant

7. Testing
   - Test plan
   - Test cases
   - Test logs (input, expected output, actual output, pass/fail)

8. Output Screens
   - GUI layouts
   - Screenshots

9. Conclusions
   - Summary
   - Limitations
   - Lessons learned
   - Further enhancements/recommendations

10. References / Bibliography

11. Appendices (if any)
