## Reusable template for other projects

**Part A: Opening**

1. **Title slide:** project name, course or semester, institution, department
2. **Introduction:** 4 cards, each with a heading and one line. Cover what the system is, security or access, the core data it manages, and a key extra capability.
3. **Problem Description:** 4 numbered problems, each with a short heading and one line on the pain it causes

**Part B: System Design** 4. **Chapter divider:** "System Design" with a one-line summary 5. **Data Flow Diagram:** the diagram plus 2–3 bullets on who uses which modules 6. **UML Diagrams:** Class diagram and Use Case diagram, each with a one-line caption
_(Optional: Database Design, which the guidelines on slide 23 ask for)_

**Part C: Modules** (repeat one slide per module) 7. **Chapter divider:** "Modules Description" 8. **One slide per module:**

- Module name as the title
- A role badge, such as "ADMIN / HR ONLY"
- Screenshot
- "Key Features" with 3–5 bullets: what the list shows, who can see it, what actions are allowed (add, edit, delete, approve), and the filters or view options
- Optional callout with the business benefit

**Part D: Implementation** (repeat one slide per screen) 9. **Chapter divider:** "Implementation" 10. **One slide per screen** (Login, Dashboard, Profile, and so on): - Screen name as the title - A subheading, such as "Secure Authentication Interface" - Screenshot - 2–3 bullets on fields, columns and buttons - Optional extras: key numbers (for a dashboard), a data table, or tab cards
_(Optional: Testing approach and Tools & Technologies, which the guidelines on slide 24 ask for)_

**Part E: Closing** 11. **Source Code:** one line of description plus the repository link 12. **Conclusions:** 4 outcome cards, for example efficiency, data accuracy, time and cost savings, and usability 13. **References:** numbered sources, each with a name and a one-line description
